# 라이브 매칭 시나리오 (실제 Claude API)

사진·위치·태그가 있는 글 쌍을 HTTP 로 올리고, **서버가 실제 Claude API 로 매칭한 결과**를 기대값과 비교해 표로 보여 준다.
UI 가 필요 없고, 이 스크립트는 `ANTHROPIC_API_KEY` 를 **읽지도 필요로 하지도 않는다**(키는 API 서버 프로세스의 환경 변수에만 있다).
비용이 드는 테스트이므로 자동 실행(CI·`pnpm test`)에 포함되지 않는다.

## 실행

```bash
# 1) 호출 수만 확인(네트워크 호출 없음, 사진만 생성)
node test/live/run.mjs --dry-run

# 2) API 서버를 키와 함께 띄운다(키는 서버 .env 에서만 읽힘). 서버 쪽 상한도 함께 거는 것을 권장:
#    AI_DAILY_CALL_LIMIT=60 pnpm start        # 재시도 포함 실제 HTTP 호출 기준
# 3) 실행(확인 플래그 필수)
LIVE_CONFIRM=1 API_URL=http://localhost:4000 node test/live/run.mjs
```

| 환경 변수 | 기본 | 설명 |
|---|---|---|
| `LIVE_CONFIRM` | (없음) | `1` 이 아니면 호출 수를 보여 주고 종료(종료 코드 2) |
| `API_URL` | `http://localhost:4000` | 대상 API |
| `ORIGIN` | API_URL 의 origin | 상태 변경 요청에 붙이는 Origin. 서버 `ALLOWED_ORIGINS` 또는 자기 자신과 일치해야 한다 |
| `LIVE_TIMEOUT_S` | 120 | 글 1건당 매칭 완료 대기 |
| `LIVE_CLEANUP` | (없음) | `1` 이면 끝에 글을 닫고(DELETE /posts) 테스트 계정 3개를 삭제(DELETE /me) |
| `LIVE_SENSITIVE` | (없음) | `1` 이면 민감 사진 항목을 PASS/FAIL 로 판정(아래) |
| `LIVE_SAVE_PHOTOS` | (없음) | 생성한 사진을 이 폴더에 저장(눈으로 확인용) |
| `LIVE_PASSWORD` | 내장 값 | 테스트 계정 비밀번호 |

## 시나리오 (사용자 3명, 글 10건, 사진 글 8건)

| 항목 | 분실 | 습득 | 기대 |
|---|---|---|---|
| S1 실제 일치 | A: 별 스티커 검은 이어폰 케이스(학생회관 1층) | B: 같은 물건, 다른 배경·기울기(학생회관 2층) | AUTO/HIGH |
| S2 닮은 물건 | (S1 의 분실글) | B: 검은 케이스지만 모양·장식 다름(은색 고리·빨간 끈), 별 없음 | AUTO 금지, S1 보다 낮은 순위 |
| S3 실제 일치 | A: 남색 우산(흰 줄·나무 손잡이·노란 이름표, 도서관) | C: 같은 우산 | AUTO/HIGH |
| S4 비일치 | A: 파란 물병(자연과학관) | B: 갈색 지갑(자연과학관) | 후보에 없음 |
| S5a/b | C: 사진 없는 검은 이어폰 케이스 분실글 | S1·S2 의 습득글 | AUTO 가 아니면 PASS(로컬 점수가 임계 미만이라 후보로만 남는 것이 일반적). AUTO 가 나오면 **WARN**(FAIL 아님) |
| S5c | A 의 우산 분실글(사진) | B: 사진 없는 우산 습득글 | 위와 동일 |
| 민감 사진 | — | B: 가짜 학생증 사진 | (아래) |

- 사진은 `photos.mjs` 가 sharp + SVG 로 **직접 그린 합성 이미지**다(저작권·개인정보 없음). 학생증은 `FAKE UNIVERSITY / HONG GILDONG (FAKE SAMPLE) / 0000-0000-0000` 이다. 글꼴 문제를 피하려고 영문·숫자만 쓴다.
- 글은 한 건씩 만들고 `matchState` 가 `PENDING` 을 벗어날 때까지 기다린 뒤 다음 글을 만든다(결정적 순서, 글별 지연 측정). 이후 분실자·습득자 양쪽에서 `/posts/{id}/matches`, `/notifications` 를 읽어 표로 출력한다.
- AI 근거(`aiReason`)는 **숫자를 `#` 로 가려** 출력한다(번호류가 근거에 섞여도 로그에 남지 않게).

## Claude 호출 상한(비용 보호)

- 스크립트가 실행 전에 **예상 호출 수**를 출력한다: 속성 추출 8회 + 직접 비교 약 15회 ≈ 23회. 최악(기존 DB 의 사진 글이 많아 글마다 `MATCH_TOP_N`=5 회 비교) 48회.
- 하드 상한: 사진 포함 글 ≤ 12, 최악 호출 ≤ 60. 넘으면 실행하지 않는다(종료 코드 2). 서버 `MATCH_TOP_N` 을 5 보다 크게 바꾸면 최악 추정이 부정확해지므로 상한(`AI_DAILY_CALL_LIMIT`)을 함께 건다.
- 기존 DB 에 사진 글이 많으면 후보 비교가 더 일어난다. 가능하면 **깨끗한 DB** 에서 실행한다.

## 판정

| 판정 | 의미 |
|---|---|
| PASS | 기대와 일치 |
| WARN | 사진 없는 쌍이 AUTO 로 승격됨(서버 기본 `NOPHOTO_AUTO_NOTIFY=true` 에서는 정책상 가능 — 일반 AUTO 규칙·임계 0.85. 막으려면 서버에 `NOPHOTO_AUTO_NOTIFY=false`). 또는 기대에 못 미치지만 실행 조건 탓일 수 있음(AI 근거가 하나도 없으면 degraded 로 보고 AUTO 미달·순위 역전을 WARN 으로 표시) |
| FAIL | 오탐(닮은/비일치가 AUTO·후보)이거나 AI 사용 중인데 순위 역전·미탐 |

종료 코드: FAIL 이 있으면 1, 아니면 0. 상세 결과는 `test/live/out/live-<stamp>.json`(git 제외).

## 민감 사진 점검(학생증)

민감 사진은 작성자에게만 원본, 다른 사용자에게는 흐림 사본이 내려간다(설계: `docs/dev-plan-backend.md` 17절). 스크립트는 다음을 측정한다:

- 작성자·비작성자(로그인)·비로그인으로 **원본 URL** 을 요청해 HTTP 상태·크기·선명도(원본 대비 블러 차이)를 출력한다.
- 비작성자가 글 상세에서 받는 **흐림 사본 URL**(`isBlurred=true`)을 따로 요청해 상태·크기·선명도를 출력한다.

`LIVE_SENSITIVE=1` 의 **PASS 조건**: ① 비작성자·비로그인의 원본 URL 이 non-200(404/401) **그리고** ② 흐림 사본이 200 **그리고** ③ 흐림 사본÷원본 선명도 비가 0.6 미만(눈에 띄게 흐릿함). 하나라도 어긋나면 FAIL 이다.

## 이 스크립트 자체의 검증(키 없이)

서버에 키가 없으면 매칭은 로컬 점수만 쓰는 degraded 로 돌아간다. 이때 기대되는 출력: 모든 글 `matchState=DONE`, 후보는 전부 `CANDIDATE`, AI 근거 없음, 알림 0건, 요약에 WARN, 그리고 "AI 근거가 없습니다" 경고. 이 모드로 스크립트의 가입·업로드·폴링·표 출력·정리 흐름을 확인했다.

## 알려진 한계

- 같은 IP 에서 시간당 5명 가입 제한(운영 설정)에 걸리면 429 로 중단한다(서버를 `NODE_ENV=test` 로 띄우거나 대기). `LIVE_CLEANUP` 도 계정 삭제 제한(5/시간)을 쓴다.
- 합성 SVG 사진은 실제 사진보다 단순해서 모델이 "unknown" 을 많이 낼 수 있다. 결과는 파이프라인 연동·정책 검증용이지 정확도 지표가 아니다.
- 기대값(AUTO/HIGH 등)은 서버 기본 임계값(0.80)과 모델 응답에 의존한다. 임계값·모델을 바꿨다면 기대를 조정한다.
